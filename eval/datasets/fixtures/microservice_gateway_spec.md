# 微服务网关与通信架构规范

## 1. 流量接入与超时控制
微服务网关作为整个系统的流量接入入口，负责所有业务微服务与下游大模型代理的统一反向代理与动态路由。
为保障系统吞吐量并防止慢请求占用连接，网关对下游接口设置严格的超时阈值。
全局接口超时参数为 timeout，其统一配置阈值为 5000 毫秒（即 5 秒）。
当针对大模型服务端推理耗时超过 5000ms 时，网关将主动中断 HTTP 传输连接，并向客户端抛出 504 Gateway Timeout 异常响应。
对于具有幂等性的 GET 查询请求，系统允许在超时后自动发起最多 2 次重试，重试退避间隔 initial_interval_ms 为 500 毫秒；非幂等性的 POST 请求严禁自动重试。

## 2. 异步连接池参数配置
网关底层采用高性能异步 HTTP 客户端连接池以复用 TCP 连接，减少握手开销。
连接池核心参数定义如下：
最小空闲连接数 min_idle 配置为 10，保证基础并发流量的即时响应；
最大并发连接数 max_connections 设定为 100，作为系统单节点的刚性上限；
连接获取超时时限 acquire_timeout_ms 设为 3000 毫秒。
在业务高峰期，若可用连接数耗尽且等待处理队列长度超过 200 时，系统将立刻触发弹性背压告警（BackpressureWarning），并启动排队限流策略以保护下游服务。

## 3. 分布式鉴权与无状态令牌
网关层承担系统无状态安全认证职责，采用基于非对称加密算法 RS256 签名的 JSON Web Token (JWT) 进行用户身份鉴权。
颁发的 Access Token 具有严格的时效控制，其标准有效期配置为 72 小时。
网关本地维护公钥证书内存缓存，公钥缓存失效周期 TTL 为 3600 秒，以避免频繁向认证服务拉取证书导致性能损耗。
用户登出或权限回收时，网关通过 JTI 唯一黑名单机制在有效期内撤销该令牌访问权。

## 4. 会话持久化与传输加密
用户的多轮对话上下文历史、会话临时黑名单凭证与限流计数器统一持久化至 Redis 高可用集群（采用主从哨兵与分片部署模式）。
在网络通信层面，网关公网接入层强制启用 TLS 1.3 传输加密，支持端到端双向数字证书验证与安全卸载。
跨域资源共享（CORS）策略实施严格域名白名单校验，生产环境严禁配置通配符 *，防止跨站请求伪造与数据泄露。
