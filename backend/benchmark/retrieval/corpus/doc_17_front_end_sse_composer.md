# 前端阅读流与悬浮输入框交互设计规范

## 1. 桌面端居中自适应阅读流（840px Max-Width）
AgentStudio-RAG 前端基于企业级现代 AI 产品的视觉交互规范重构，深度参考 ChatGPT 与 Claude 的优秀阅读体验。
主工作台聊天视口摒弃了传统后台管理系统充满整个宽屏导致行宽过长、视线疲劳的弊端，采用严格居中的黄金阅读流布局。
消息气泡容器的最大宽度（`max-width`）严格约束为 840 像素（840px），在屏幕宽度超过 1400px 时两侧自动留白居中。
这一设计确保单行中文阅读字符数稳定在 45 到 65 个汉字之间，符合人类工效学最佳视线移动跨度，并在 1366×768 笔记本与 1920×1080 大屏之间保持高度一致的视觉节奏。

## 2. 一体化悬浮输入框（Floating Composer）架构
前端彻底重构了此前分散在页面不同区域的操作入口，打造了现代化一体式悬浮输入卡片 ChatComposer（位于 `components/ChatComposer.tsx`）。
输入卡片采用 16px 大圆角设计，内嵌多行自适应文本域（Textarea），支持用户在输入长文本时自动从单行平滑拉伸至最高 200 像素，超出后自动开启内部平滑滚动条。
卡片上方集成多附件状态托盘，实时预览已拖拽挂载的 PDF、DOCX、TXT、MD 文件及其解析进度条；
键盘交互遵循标准化桌面端习惯：按下 Enter 键直接提交发送，按下 Shift + Enter 执行换行排版；在流式生成期间，发送按钮平滑过渡为红色的圆形停止按钮（Stop Button）。

## 3. AbortController 流式中断与响应式状态恢复
前端通过标准现代浏览器的 `fetch` API 配合 `ReadableStreamDefaultReader` 实现底层的 Server-Sent Events 流式事件帧解析。
在每次发起会话提问的一瞬间，前端初始化独立的 `AbortController` 实例并将其引用挂载至 `abortControllerRef`。
当用户点击停止生成按钮或切换左侧历史会话时，前端直接触发 `abortController.abort()` 信号，底层浏览器网络栈瞬间向后端发送 TCP FIN 报文中断连接；
同时，前端通过响应式状态机瞬间将输入框恢复为可用编辑状态，重置光标焦点，并为当前回答气泡打上“已停止”标签，绝不卡死用户界面。

## 4. Markdown 生产级排版与超宽表格横向自适应
大模型生成的回答通常包含大量格式丰富的多语言代码片段、层级列表与复杂 Markdown 对比表格。
系统自主研发了独立的 MarkdownRenderer 组件（位于 `components/MarkdownRenderer.tsx`），针对流式打字机场景做了深度适配：
- 代码块展示：顶部呈现半透明灰色语言标签，右侧集成防重复触发的“一键复制代码”图标按钮，代码容器设置横向滚动（`overflow-x: auto`）且坚决禁止撑破外层 840px 容器；
- 表格自适应：对于包含大量对比列的超宽表格，外层包裹无感滚动条，表头单元格与奇偶行采用柔和交替浅灰底色（`#f8fafc`），单元格行高固定为 1.75 倍以提供通透阅读感。

## 5. 左侧会话侧栏自然时间分组（260px Width）
前端左侧历史会话管理侧栏固定宽度为 260 像素（260px），具备一键折叠收起能力以最大化阅读视野。
历史会话列表摒弃机械的分页翻页模式，采用用户心理模型最亲和的自然时间维度进行自动分组：
- “今天”（Today）
- “昨天”（Yesterday）
- “最近 7 天”（Previous 7 Days）
- “更早”（Older）
会话项具备悬停淡入的独立重命名与垃圾桶删除图标，并支持自动识别首句提问动态截取前 30 个字生成会话标题，大幅降低用户的历史管理认知负担。
