# 跨工具全局证据追踪与确定性引用溯源规范

## 1. 跨工具证据追踪痛点与 EvidenceRegistry 定位
在多步 Agent 协同推理中，智能体通常会先后调用多种不同来源的检索工具（例如第一步调用 `search_knowledge_base` 查企业规范，第二步调用 `search_conversation_attachments` 查用户上传的日志附件）。
如果缺乏全局的证据协调中枢，各工具各自独立返回切片并在其 Observation 中输出局部的引用标记，将导致致命的上下文混乱：
一是两个工具可能重复召回相同的切片内容，导致模型上下文严重冗余；
二是各工具内部各自编号的 `[Ref-1]`、`[Ref-2]` 会在 Prompt 中发生冲突，导致模型最终输出的引用序号产生歧义。
为此，系统在 Agent 运行时底层构建了全局唯一的证据账本 EvidenceRegistry（定义于 `app/agent/tools/evidence.py`）。

## 2. 全局哈希去重与引用编号单调自增
EvidenceRegistry 专属于单次 Agent Run 作用域，在每次提问启动时独立实例化以保障跨请求隔离。
账本核心维护了切片唯一标识映射 `_chunks_by_id` 与引用序号映射 `_ref_id_by_chunk_id`。
当任何工具尝试向账本注册检索到的切片时，账本首先基于切片的全局唯一 `chunk_id` 执行去重判断：
若该切片此前已被其他工具或前置步骤注册过，账本自动复用首次分配的引用序号，不增加新项；
若该切片为全新发现，账本将全局自增计数器累加 1，为其分配全局递增且不重复的序号（如 [Ref-1], [Ref-2], ... [Ref-N]），并在所有工具观察结果中保持一致的全局引用格式。

## 3. 并发安全保护与上下文容量硬约束
在未来支持并行多工具调用的扩展架构下，多个工具协程可能同时向证据账本写入切片。
EvidenceRegistry 内部采用 `threading.Lock()` 互斥锁保护所有内部字典与列表状态，确保并发注册时计数器不发生竞争条件（Race Condition）。
此外，账本内嵌了双重容量防护机制以防止失控的多步工具调用导致 Agent 上下文瞬间击穿模型窗口：
- `max_evidence_chunks`：硬性限制单次运行最多收集的切片上限为 20 个；
- `max_total_evidence_tokens`：硬性限制所有已收集切片折算的累积总 Token 数上限为 4000 tokens。
超出阈值的切片被静默拦截，绝不流入下游 Prompt。

## 4. CitationExtractor 确定性后验核验规则
大模型在根据切片证据生成最终回答时，经常发生虚构引用标记的幻觉现象（例如知识库仅提供了 3 个切片，模型却在回答末尾凭空标上 `[Ref-8]`）。
系统在快速问答引擎与 Agent 收尾节点（`citation_verifier_node`）中统一挂载了确定性后验核验器 CitationExtractor（位于 `app/rag/citation.py`）。
核验器执行严格的白名单校验：
首先通过正则模式 `r"\[Ref-(\d+)\]"` 扫描回答文本中真实出现的所有引用标记；
随后逐项比对标记编号 X 是否满足边界条件：$1 \le X \le 	ext{len}(	ext{retained\_chunks})$；
任何超出实际切片数量的虚构编号被立即无情剔除，合法引用按首次出现顺序去重，并严格与数据库底层切片的真实凭据进行元数据绑定。

## 5. 多文档溯源标签与前端透视交互
经 CitationExtractor 核验后的每个合法引用会被打包为标准的 `Citation` 数据结构，携带丰富的物理溯源元数据向前端暴露。
根据切片的实际来源格式，系统生成统一的人类可读溯源标签（`provenance_label`）：
- PDF 文档：展示为精准物理页码（例如“第 2 页”）；
- DOCX 文档：展示为章节路径大纲及段落块序号（例如“章节: 3.1 核心机制 | 块: #4”）；
- Markdown 文档：展示为完整多级大纲路径（例如“章节: # 容灾规范 > ## 2. 熔断”）；
- TXT 纯文本：展示为起始与结束行号（例如“行号: 第 12-28 行”）。
前端在渲染回答时将 `[Ref-X]` 呈现为可点击的蓝色高亮徽章，用户点击后立即滑出抽屉展示对应的原文切片，实现真正的“字字有出处，处处可核实”。
