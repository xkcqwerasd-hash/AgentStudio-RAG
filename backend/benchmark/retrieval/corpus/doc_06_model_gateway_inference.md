# 大模型推理网关与流式并发调度规范

## 1. OpenAI 兼容协议反向代理中枢
大模型推理网关负责统一桥接外部商业大模型 API（如 DeepSeek-V3 官方接口、Azure OpenAI）与企业内部私有化部署的开源大模型推理引擎（如 vLLM、Ollama）。
网关对外统一暴露标准化的 OpenAI Chat Completion 协议接口（`/v1/chat/completions`），对各异构底层服务进行抹平与转换。
系统通过动态模型解析工厂（`resolve_llm_client`）在请求级别解耦模型配置，支持根据用户传入的 `model_id` 实时路由至对应的云端服务端点或内网本地 GPU 推理集群。
网关自动执行入参格式清洗，剥离目标模型不支持的多余专有参数，确保客户端请求参数的透明通用性。

## 2. 流式 Server-Sent Events (SSE) 协议规范
为了大幅降低首字响应时间（Time to First Token, TTFT）并提供丝滑的打字机交互体验，网关端到端采用 Server-Sent Events (SSE) 流式传输协议。
响应的 HTTP 响应头强制声明 `Content-Type: text/event-stream`、`Cache-Control: no-cache` 以及 `Connection: keep-alive`。
系统定义了规范化的生命周期流式事件序列：
- `start`：宣告流式启动，返回初始会话 ID 与用户消息 ID；
- `retrieval`：携带检索阶段耗时、召回切片数及候选池元数据；
- `token`：大模型生成的单个文本 Token 增量增量切片；
- `citations`：后验核验完成的正式事实证据引用列表；
- `trace`：包含执行步骤、Token 预算消耗及全流程耗时的分析报告；
- `done`：宣告全流程结束并返回最终 Assistant 消息实体 ID。

## 3. 客户端异常断开与协程取消处理机制
在长文本生成或复杂多步思考过程中，用户经常会在生成未结束前主动点击前端“停止生成”按钮，或直接关闭浏览器网页标签。
此时网关层底层基于 Python 协程框架会立即捕获到由操作系统管道中断触发的 `asyncio.CancelledError`。
系统在执行引擎中对该取消异常进行防御性捕获：
系统绝不发生崩溃或引发数据库连接泄漏，而是首先截断当前已经积累生成的文本并在末尾追加固定标识 `

[回答已被用户中止]`；
随后系统仅提取当前已生成文本所真实关联的部分引用，安全调用数据库事务的 `await db.commit()` 持久化半截回答，最后释放所有协程资源。

## 4. 动态 Token 预算管理与上下文装箱
大模型具有物理固定的最大上下文窗口容量（Context Window），若直接将长历史对话与大量检索切片拼接输入，极易击穿窗口触发 HTTP 400 报错。
系统自研的上下文预算管理器 `ContextBudgetManager` 实施严格的数学装箱策略。
管理器首先根据模型总窗口（如 32768 tokens）扣减预留的系统输出配额 1500 tokens 与安全边距 256 tokens，得出可用的纯输入预算池。
随后系统以对话轮次（Turn-based）为最小原子单元，成对剔除过早的历史消息，优先保障最近的一轮完整 QA 对；
最后对检索切片按照精排相关度从高到低贪心装箱，一旦累计 Token 超过切片预算硬上限，立即截断停止，坚决防止上下文爆炸。

## 5. 模型健康探测与就绪探针规范
网关内置全自动的模型节点心跳探测与就绪检测机制（Readiness Probe）。
网关通过异步 HTTP 客户端对已配置的模型服务商端点执行周期性健康检查，针对通用模型通过伪查询探测 `/health` 或发送零 Token 握手包。
探测操作严格配置 3000 毫秒（即 3 秒）的硬性调用超时阈值；若某模型节点连续 3 次探测发生网络超时或返回 5xx 故障，系统自动将该模型配置标记为 `enabled = False`。
此时前端模型选择列表自动将该不可用模型置灰并向管理员控制台抛出告警，彻底避免用户请求持续被派发给已宕机的服务商。
