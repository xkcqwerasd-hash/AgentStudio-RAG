# 企业多租户架构与 RBAC 访问控制规范

## 1. 逻辑多租户架构与共享数据库隔离
在面向大型企业集团不同子公司或独立部门的部署方案中，系统采用高性价比的“共享应用实例、共享数据库、逻辑行级隔离”（Shared Database, Shared Schema）多租户架构。
系统全局实体均打上全局唯一的租户键 `tenant_id`，底层数据库配合 PostgreSQL 行级安全策略（Row Level Security, RLS）与 ORM 查询拦截器确保数据隔离。
应用层网关在收到请求后，通过 JWT 验签提取该请求所属的合法租户身份，一旦发现客户端尝试通过伪造 URL 参数访问属于其他租户的 `knowledge_base_id`，拦截器在 SQL 执行前抛出 HTTP 403 Forbidden 权限拒绝。

## 2. 基于角色的权限访问控制（RBAC）模型
系统内嵌标准的基础角色权限访问控制体系（Role-Based Access Control, RBAC），将系统操作权限细化解耦为三个标准角色等级：
- 超级管理员（Super Admin）：拥有最高系统配置权限，可进行模型服务商增删、API Key 维护、全局审计日志查看及全量租户资源分配；
- 知识库管理员（Knowledge Manager）：拥有特定知识库的管理权限，支持新建知识库、上传/重新解析/删除技术文档，以及微调切片分块参数；
- 普通用户（End User）：仅拥有只读检索与问答权限，可创建个人历史对话、上传会话级临时私有附件、发起提问与查看引用溯源，严禁修改公共知识库。

## 3. 细粒度知识库授权与读写分离控制
在集团多部门协同环境中，不同的知识库具备差异化的机密级别（例如“财务薪酬规范”对全员保密，而“微服务网关规范”对全体研发团队开放）。
系统支持以知识库（KnowledgeBase）为最小粒度建立访问授权列表（Access Control List, ACL）。
授权策略支持按用户个人、所属部门组织或预设用户组进行绑定；
在执行 RAG 检索时，`VectorRetriever` 与 `BM25Retriever` 自动读取当前用户的授权知识库集合 ID 列表，并在数据库查询的 WHERE 条件中注入强制过滤，从根源上消除跨部门数据越权刺探风险。

## 4. 敏感数据静态加密与动态脱敏规则
除在第 09 篇规范中详述的 API Key 加密与 PII 手机号脱敏外，系统对高敏感租户配置数据实施静态落盘加密（Encryption at Rest）。
数据库敏感字段在落库前由 ORM TypeDecorator 自动截获并调用底层加密算法加密为密文字符串，仅在读取进内存执行业务逻辑时瞬时解密；
针对前端展示接口，响应 DTO 必须经过脱敏清洗器：例如返回给普通用户的知识库列表仅展示脱敏后的模型名称，隐藏实际底层云端厂商的具体 Base URL 与鉴权 Token，防范商业机密泄露。

## 5. 跨租户资源配额与并发限速管控
为了防止某一个高负载租户突发海量文档上传或大量并发长文本分析请求从而耗尽集群全局计算资源，系统构建了细粒度的多租户资源配额管理（Resource Quotas）。
系统针对每个租户配置硬性配额参数：
- 知识库总数配额（如每个租户最多创建 20 个知识库）；
- 存储容量配额（如租户总文件存储上限 10GB）；
- 向量切片上限（如单个租户最多容纳 50,000 个切片）；
- 并发请求速率（通过分布式 Redis 令牌桶实施单个租户最大并发连接数 50 QPS 的严格限制），保障集群整体的平稳多租户公平调度。
