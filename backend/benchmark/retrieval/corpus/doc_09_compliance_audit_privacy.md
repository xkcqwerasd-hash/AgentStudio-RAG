# 数据安全、合规审计与隐私保护规范

## 1. PII 敏感信息脱敏与数据分类分级
系统严格遵循欧盟通用数据保护条例（GDPR）与《中华人民共和国个人信息保护法》的技术要求，对所有经过系统处理的文本数据实施严密的分级防护。
系统将数据安全级别由低到高划分为 L1（公开数据）、L2（内部非敏感）、L3（重要业务数据）以及 L4（个人敏感身份信息 PII）。
在用户上传包含个人敏感数据的文档或在聊天框输入包含身份证号、手机号码、真实姓名与银行卡号的文本时，系统在数据进入 Embedding 模型向量化或持久化存入数据库之前，强制前置调用敏感信息脱敏过滤器。
脱敏过滤器采用高性能正则表达式与命名实体识别组件，将手机号自动转换为 `138****8888` 掩码格式，杜绝未经授权的明文信息落盘存储。

## 2. API Key 对称加密与主密钥持久化
大模型服务商的 API 调用凭据（API Key）属于系统核心敏感资产，严禁以任何明文字符串形式直接存入数据库或打印输出至应用日志。
系统采用工业级对称加密算法 Fernet 实施持久化密文保护。
根据安全规范，Fernet 底层严格基于 AES-128-CBC 模式执行数据块对称加密，并使用 HMAC-SHA256 生成 128 位签名认证标签以校验密文完整性与防篡改。
系统的加解密主密钥（Master Key）遵循严格的来源优先级策略：优先读取生产环境变量配置 `MODEL_ENCRYPTION_KEY`；若环境变量未显式提供，则自动在受操作系统文件权限严格保护的本地安全存储目录生成 `.model_master_key` 密钥文件。

## 3. 密钥定期轮换与安全吊销机制
为了有效防范主密钥长期不发生变化带来的密码分析与凭据泄露风险，系统制定了周期性的密钥轮换（Key Rotation）操作规程。
安全规范建议系统的 API Key 加密主密钥每隔 180 天进行一次主动轮换。
在密钥轮换过程中，系统支持多版本密钥共存机制：新写入的 API Key 统一采用最新的版本密钥进行加密，同时保留旧版本密钥供存量历史密文解密使用，待存量数据全部平滑重新加密后，方才安全注销旧密钥。
一旦发现任何潜在的密钥泄露嫌疑，安全管理员可执行紧急一键吊销，系统瞬间抹除内存密钥并迫使所有服务重新完成密文验证。

## 4. 操作审计日志留存与只读合规策略
系统对所有管理员操作事件、知识库文档增删改操作以及大模型推理调用的 Trace 元数据执行全程审计日志记存。
依据国家网络安全法的合规硬性要求，所有审计日志记录必须在独立于业务数据库的专用日志冷存储归档中妥善保存不少于 180 天以备监督核查。
审计日志存储介质强制开启 WORM（Write Once, Read Many）一次写入多次读取合规策略，任何具备管理员权限的用户均无法对已生成的历史审计日志执行修改或部分删除操作。
审计日志包含完整的时间戳、操作者唯一身份、客户端源 IP 地址、操作行为类型及前置后置状态差异。

## 5. 数据主权隔离与本地私有化部署
对于金融、政企与医疗等涉及高度数据隐私与合规红线的应用场景，系统严格支持完全脱离公网环境的本地私有化闭环部署。
在此部署形态下，系统所依赖的 PostgreSQL 数据库、向量索引切片、Redis 缓存以及 BGE-small 嵌入模型和本地 DeepSeek/Qwen 大模型推理节点全部置于企业内部局域物理内网。
系统网络层严格阻断任何外部公网的主动出站连接，所有用户上传的内部机密文档与交互问答数据仅在本地私有服务器内存与磁盘中流转，彻底消除核心数据跨境或外泄的法律合规风险。
