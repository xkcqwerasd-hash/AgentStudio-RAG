# 向量数据库索引机制与相似度检索架构

## 1. Dense 稠密向量表征与 BGE 嵌入模型
稠密向量检索（Dense Retrieval）是现代 RAG 架构理解长程语义与概念相似度的核心技术基石。
系统默认选用北京智源人工智能研究院开源的 BAAI/bge-small-zh-v1.5 作为基准嵌入模型，该模型将任意变长文本切片映射到 512 维的稠密连续向量空间。
嵌入模型在将文本编码为浮点向量后，强制执行 L2 模长归一化（Normalize Embeddings），使得所有切片向量均分布在 512 维超球面的表面（即向量模长恒等于 1.0）。
在此数学前提下，两个文本向量的点积运算（Dot Product）在数值上完全等价于两者之间的余弦相似度（Cosine Similarity），从而大幅精简相似度计算的计算复杂度。

## 2. 余弦相似度计算与零向量安全防护
在系统的 VectorRetriever 实现中，向量相似度由 NumPy 底层加速库在应用内存中执行批量矩阵乘法。
针对查询向量 q 与切片向量 d，余弦相似度数学公式为：
$$	ext{CosSim}(q, d) = rac{q \cdot d}{\|q\|_2 \|d\|_2}$$
为防止异常输入（如纯空白字符或损坏的向量）引发浮点除以零异常（ZeroDivisionError），代码层设置了严格的模长安全阈值检查：
若查询向量或切片向量的 L2 范数小于 $10^{-9}$，系统防御性返回相似度 0.0 并记录警告日志，有效保障了检索服务在极端畸形数据下的高可用鲁棒性。

## 3. 高维图索引 HNSW 与近似最近邻算法
当知识库切片规模从数百扩展至数百万级别时，线性全量余弦遍历（Exact KNN）的耗时将呈线性爆炸，此时必须引入近似最近邻（ANN）图索引算法。
工业界首选的索引结构为分层可导航小世界图（Hierarchical Navigable Small World, HNSW）。
HNSW 算法将高维向量组织成多层具备跳跃表（Skip-List）特性的网络拓扑图结构：
最顶层拥有较长的边跨度和稀疏节点，用于极速粗定位；随着层级逐步向下，图结构趋向密集，搜索步长逐层收敛并最终在最底层的全量节点网络中锁定最近邻候选。
HNSW 具备对数级 $O(\log N)$ 的极高搜索时间复杂度，召回率通常可逼近 98% 以上。

## 4. 倒排量化索引 IVFFlat 与内存压缩技术
在单机物理内存资源受限的部署场景下，IVFFlat（Inverted File with Flat Vectors）成为兼顾内存占用与构建速度的轻量化选择。
IVFFlat 采用 K-Means 聚类算法预先将连续的向量空间划分为数百至数千个 Voronoi 细胞（Voronoi Cells），每个细胞由一个聚类质心向量（Centroid）代表。
在执行检索时，算法仅需计算查询向量与各个质心的距离，随后只在距离最近的少量细胞列表（`nprobe` 参数控制）内部进行精细扫描，大幅裁剪 90% 以上无关切片的点积运算。
结合乘积量化（Product Quantization, PQ）技术，可将 32 位浮点数压缩为 8 位整数，使向量常驻内存体积剧降 75%。

## 5. 当前全量线性扫描的实现机制与演进边界
经审计确认，AgentStudio-RAG 当前版本的 `VectorRetriever` 在实现上采用了“全量数据库加载 + NumPy 内存点积”的轻量化无外部依赖模式。
切片向量以标准 JSON 数组字符串形式持久化于 `document_chunks.embedding_json` 字段中。
在知识库切片数处于 10,000 个以内的中小型企业场景下，NumPy 矢量化并行计算能够在 10 毫秒以内完成全库扫描，具备极高工程收益且无需维护复杂的外部向量数据库集群；
然而，当切片数量迈向 50,000 以上的超大规模时，该方案面临全表扫描 I/O 耗时与内存激增瓶颈，后续版本需原生迁移至 PostgreSQL 的 pgvector 扩展并挂载 HNSW 索引。
