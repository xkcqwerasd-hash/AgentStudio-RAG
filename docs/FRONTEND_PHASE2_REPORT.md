## 1. 实施背景与用户问题溯源

在 Phase 1 完成全局导航和主题瘦身之后，根据用户提供的生产实际运行截图（如图中问答会话 `5ffbeac7-4300-40f4-b0ab-8a44d6af044c`）：

- **原始纯文本问题**: 聊天主消息使用原生的 `<div style={{ whiteSpace: 'pre-wrap' }}>{msg.content}</div>` 渲染。大模型输出的 Markdown 格式（如 `**5000 毫秒（即 5 秒）**`、`**5 秒**`）直接以原始星号文本暴露给终端用户。
- **正文引用死文本问题**: 正文中的引用标记如 `[Ref-1]` 直接以死文本字符串混杂在段落中，用户无法在阅读过程中直接悬停预览来源，也无法在正文中直接点击唤起证据抽屉。
- **排版体验粗糙**: 段落间距、代码展示、表格和列表缺乏现代成熟 AI 产品（如 ChatGPT、Claude）的层次感与阅读舒适度。

Phase 2 重点攻克上述问题，独立封装高内聚、流式感知的 `MarkdownRenderer.tsx` 组件，并无缝接入 `ChatPage.tsx`。

## 3. 核心组件架构与技术实现

### 3.1 零依赖流式感知 AST 架构

`MarkdownRenderer.tsx` 采用双层解析流水线：

```
[原始 LLM 流式文本 / 历史会话]
              │
              ▼
   parseBlocks (块级语法分块)
              │
    ┌─────────┼─────────┬─────────┬─────────┬─────────┐
    ▼         ▼         ▼         ▼         ▼         ▼
  标题(H1-6) 代码块   表格     引用块    列表     段落
 (Heading)  (Code)   (Table)  (Quote)   (List)   (Para)
    │         │         │         │         │         │
    └─────────┴────┬────┴─────────┴─────────┴─────────┘
                   ▼
       renderInline (行内 Token 解析流水线)
                   │
    ┌──────────────┼──────────────┬──────────────┐
    ▼              ▼              ▼              ▼
粗体/斜体/删划   行内代码       超链接      [Ref-X] 引用胶囊
(Strong/Em)     (Code)         (Link)      (CitationPill)
                                                 │
                                                 ▼
                                     Tooltip 证据卡 + 唤起 Drawer
```

### 3.2 关键代码实现特性

1. **行内 `[Ref-X]` 引用胶囊交互**:
   - 使用正则 `^\[Ref-(\d+)\]` 在段落、表格单元格、列表项等所有文本位置进行优先识别；
   - 提取引用索引并自动在当前消息的 `citations` 数组中查找匹配条目；
   - 悬停浮层展示：文档全名、来源类型与页码/章节（如 `DOCX 附件 · 章节: 架构规范 > 第 2 节`）、匹配度百分比（如 `95%`）及前 100 字符文本片段；
   - 点击事件：阻止冒泡并触发 `onCitationClick(citationIndex)`，直接调用 `openCitationDetail` 打开已有的 `CitationDrawer` 并高亮对应证据卡片。
2. **多语言代码块与极客主题**:
   - 识别 ````python`、````typescript`、````sql`、````bash`、````c++`、````json` 等语言标识；
   - 顶部工具栏呈现语言标签（如 `PYTHON`）及一键复制代码按钮；
   - 深石板极客风格配色（容器 `#0f172a`，顶栏 `#1e293b`），文字不撑破气泡，支持原生横向滚动；
   - 复制状态支持 2 秒微交互动效（`<CheckOutlined /> 已复制`）。
3. **Markdown 表格**:
   - 自动解析列对齐语法（`:---` 靠左、`:---:` 居中、`---:` 靠右）；
   - 浅灰色交替斑马纹背景（`#f8fafc` / `#ffffff`），表头强化加粗；
   - 外层嵌套自适应容器 `overflowX: auto; maxWidth: 100%`，确保宽表在窄屏下平滑横滚而不挤垮卡片。
4. **中文段落阅读排版**:
   - 正文字号提升至 `14.5px`，行高锁定 `1.75`，段间距标准 `10px`（末尾段自动为 `0 0 4px 0`）；
   - 标题层次：H1 (20px, 700, 下划线), H2 (17px, 700), H3 (15px, 600), H4~H6 (14~13px, 600)；
   - 引用块带有皇家蓝装饰侧边条（`borderLeft: 3.5px solid #2563eb`），淡灰背景，温和易读。

## 5. 关键业务特性继承验证

严格遵循「关键业务特性绝对不能丢」原则：

1. **`[Ref-X]` 引用标记识别**:
   - 不丢失任何引用索引，无论位于段落中、列表中还是表格单元格中，均完整转换为可交互胶囊；
   - 兼容非标索引容错（即使检索库中无对应条目，仍作为可用交互胶囊渲染，不留生硬字符）。
2. **`CitationDrawer` 联动**:
   - 点击正文中任意 `Ref-X` 胶囊，均直接调用 `openCitationDetail(msg.citations, refIndex)`；
   - 抽屉自动滑出并聚焦高亮对应引用卡片；
   - 消息卡片底部的「真实引用事实依据 (X 处)」聚合栏目与「展开所有证据详情」按键完整保留，双向交互一致。
3. **来源追踪证明 (Provenance)**:
   - DOCX: 准确显示章节路径（`heading_path`）与段落编号；
   - Markdown: 准确显示文档章节与分块编号；
   - TXT: 准确显示起始与结束行号（`L...~L...`）；
   - PDF: 准确显示原始页码（`P.X`）。

## 6. 流式生成与容错健壮性机制

在 Workflow RAG 与 LangGraph Agent 两种模式的实时流式输出中：
- **未闭合代码块**: 当模型刚输出 ````python\ndef run():` 且尚未输出结尾 ```` 时，AST 解析器自动标识 `isUnclosed: true`，直接将其作为处于活跃输入状态的代码卡片进行渲染，光标动态挂载于代码末行，不再发生因标记未闭合而导致的界面跳闪。
- **未完成表格**: 当模型只输出表头与第一行数据时，表格解析器自动根据现有有效列补全渲染，后续行到达时平滑追加。
- **未完成行内标记**: 当模型正在输出 `**加粗文`（结尾 `**` 尚未到达）时，安全降级为普通文本展示，待闭合字符到达后即刻转换为加粗节点，绝无白屏或抛出未捕获异常。
